- 홈페이지: https://okclean-kr.github.io/
- 고객용 진입 주소: https://okclean-kr.github.io/app/
- 관리자 안내: https://okclean-kr.github.io/admin/

## 복원 범위

2026년 11월 9일 보관한 백업의 11월 3일 홈페이지 소스를 새 계정 `okclean-kr`에 맞춰 복원했습니다. 이 저장소에는 공개 홈페이지 파일만 포함합니다.

- 홈페이지, 서비스 소개 12개, 지역 소개 3개
- 시공 사례 53건과 청소 팁 5건
- 사례 사진 48개 로컬 복원; 2건은 기존 외부 이미지 주소 유지; 8건은 원래 사진 없음
- 견적 계산, 전화·문자·카카오톡 상담 연결
- 고객용 진입 경로와 기존 관리자 사이트 안내
- 새 주소에 맞춘 사이트맵, 공유 주소, 설치용 manifest 및 캐시 범위

## 2026-11-12 상담 동선 개선

첫 화면에서 실제 작업 사진과 사진 견적 문의를 안내합니다. 대표 작업 3건은 기존 블로그 기록과 로컬 사진을 연결했습니다. 예상 견적 계산기는 별도 영역에 두고, 가입·앱 설치·추천제품은 상담 흐름 뒤에 배치했습니다. 서비스 12개와 지역 3개 페이지에도 사진 상담 동선과 검색·공유 설명을 반영했습니다.

`cases.json`의 원본 58건은 보존합니다. `case-classification.json`에서 작업 기록과 청소 팁·공지·개인 기록을 구분하며, 분류 파일을 불러오지 못하면 확인된 대표 작업만 사례로 표시합니다. `featured-cases.json`에 기록한 날짜는 블로그 발행일이며 작업일을 의미하지 않습니다.

## 기능 상태

회원 신청은 `member-sync.js`의 기존 Firebase 저장 흐름을 사용합니다. 신규 저장 성공이 확인된 뒤 쿠폰을 표시하며, 친구 소개 자동 적립과 별개입니다. 이번 개선은 가격 설정과 회원 저장 구조를 바꾸지 않습니다. 기존 관리자 사이트는 `https://okclean-admin-app.web.app/admin/`입니다.

방문·견적·상담 버튼 측정 코드와 `admin/analytics.html`을 준비했습니다. 실제 수집은 `analytics-config.js`에서 `enabled: false`, `verified: false`로 꺼져 있습니다. 현재 저장된 운영 규칙에는 `site_events` 권한이 없고, 새 규칙은 미적용 초안입니다. 서버 시험 저장 및 재조회 전에는 수집 완료로 취급하지 않습니다. 상세 범위와 활성화 조건은 [측정 연결 문서](ops/analytics-measurement.md)에 있습니다.

블로그 사례 갱신 예약은 아직 연결하지 않았습니다. 보관된 원본 소스, 백업 전체, 실제 고객정보, 인증 비밀정보는 이 공개 저장소에 넣지 않습니다.

## 게시 방식

GitHub Pages는 `main` 브랜치의 저장소 최상위 폴더(`/(root)`)를 게시합니다. `index.html`과 `.nojekyll`을 이 폴더에 둡니다. 복원 브랜치가 `main`에 반영되면 기존 Pages 배포가 시작됩니다.

## 검증

`node --test tests/analytics.test.cjs`로 수집 OFF, 허용 필드와 개인정보 배제, 상담·사례·제품 이벤트 구분, 한국시간 날짜 집계를 확인합니다. JavaScript 구문, HTML 내부 참조와 앵커, 기존 가격·회원 설정 보존도 검사합니다. 이 검사는 실제 전화·문자·카카오 메시지 전송, 회원 가입, 통계 서버 저장 성공을 의미하지 않습니다.
