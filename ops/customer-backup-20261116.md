# 고객 자료 암호화 백업

## 범위와 접근

`/admin/backup.html`은 기존 Google 관리자 UID와 실제 ID Token의 Google 로그인 제공자를 확인한 뒤 조회한다. 페이지를 열기만 해서는 고객 자료를 읽지 않는다. 관리자 메뉴와 견적 관리에서 연결하며 기존 회원·견적·사진 권한과 Firebase 규칙은 변경하지 않는다.

백업 대상은 `member_requests`와 해당 ID의 `member_receipts`, `quote_requests`와 그 `photos`·`history`, 연결된 `quote_receipts`·`quote_limits`다. 실제 견적과 `test:true` 견적을 모두 포함하고 시험 건수도 표시한다. 접수증·제한 문서는 기존 권한상 목록 열람 대신 부모에서 확인한 ID로 단건 조회한다. 통계·제품·Firebase 인증 계정·부모와 연결되지 않은 고아 문서·그 밖의 컬렉션은 포함하지 않으므로 **전체 Firebase 프로젝트/DB 백업으로 표현하지 않는다.**

문서 ID 순서로 페이지를 나눠 서버 자료만 읽으며 캐시·보류 중 쓰기가 있으면 중단한다. 부모 목록·내용을 다시 읽어 내보내기 중 변경을 탐지한다. 사진 수 불일치·권한 오류·로그아웃·조회 실패·시간 또는 용량 상한은 완료로 표시하지 않는다. 여러 조회를 하나의 동일 시점 스냅샷으로 보장하는 방식은 아니다. 없는 참조 문서는 경고 수와 백업 안의 기록으로 구분한다.

## 암호화와 보관

- 직접 입력한 12~256자 암호 또는 브라우저에서 생성한 256비트 무작위 복구키를 백업 전용 암호로 사용한다. 자동 복구키는 64자리 16진수이며 화면·로그·입력란에 표시하지 않고 별도 `.okckey` 파일로만 제공한다. 서버·분석 이벤트·로그·브라우저 저장소에 기록하지 않고 작업이 끝나면 입력란을 비운다.
- Web Crypto API의 PBKDF2/SHA-256(600,000회, 무작위 16바이트 salt)로 비추출 AES-GCM 256비트 키를 유도하고 무작위 12바이트 IV·128비트 태그를 사용한다. 포맷/버전은 additional authenticated data로 고정한다. 근거: https://www.w3.org/TR/webcrypto-1/
- 암호화 파일 밖에는 고객 원문과 암호를 넣지 않는다. 문서 경로·필드·건수·경고·조회 구간도 암호문 안에 있다. 저장 시각은 Timestamp의 seconds/nanoseconds를 보존한다. 지원하지 않는 데이터 형식은 누락시키지 않고 중단한다.
- 파일을 준비한 직후 같은 암호로 복호화하고 내용·SHA-256·형식·범위를 대조한 뒤에만 다운로드 링크를 표시한다. 링크를 누르고 실제 다운로드가 끝나야 파일이 보관된 것이다. 화면 준비 성공을 실제 보관 완료로 보고하지 않는다.
- 내보내기 상한은 5,000문서·원문 20MB, 파일 재검증 상한은 30MB다. 운영 규모가 커지면 별도의 관리형 전체 백업이 필요하다.
- 파일은 `.okcbackup` 형식으로 관리자 브라우저에서 내려받는다. 파일과 암호는 별도로 보관하며 공개 저장소에 올리지 않는다. 백업 파일에도 기존 개인정보 보관·삭제 기준을 적용하고, 삭제 요청한 자료가 과거 백업에서 다시 복원되지 않도록 별도 확인한다. 암호 분실 시 복구하거나 재설정하는 기능은 없다.

## 사용 절차

1. 기존 Google 관리자로 로그인하고 범위를 확인한다.
2. `자동 복구키로 백업 준비`를 누르거나, 백업 전용 암호를 두 번 입력하고 수동 준비 버튼을 누른다.
3. 서버 조회·암호화·복호화 확인 완료와 건수·파일 체크섬을 확인한다.
4. `검증한 암호화 백업 내려받기`를 눌러 파일을 저장한다. 자동 방식은 `별도 복구키 파일 내려받기`도 눌러 두 파일을 모두 보관한다. 복구키 파일은 백업과 다른 안전한 장소에 보관한다.
5. `보관한 파일 다시 확인`에서 파일과 같은 암호 또는 복구키 파일을 선택해 재검증할 수 있다. 복구키 파일의 SHA-256과 백업 파일의 체크섬이 일치해야 복호화한다. 검증은 브라우저에서만 수행하며 서버 복원이나 변경을 하지 않는다.

자동 방식은 사용자 암호 입력 없이 진행할 수 있으며 파일용 복구키 외에 로그인 암호·Firebase 키·계정 권한을 변경하지 않는다. 직접 암호 입력 방식을 사용할 때도 채팅으로 암호를 요청하지 않는다. 실제 백업 파일과 필요한 복구키 파일 다운로드를 마치기 전에는 보관 완료로 판정하지 않는다.

## 복원 검증과 한계

`tests/backup-rules.test.mjs`는 loopback의 `demo-okclean-quotes`에서만 실행한다. 합성 회원·쿠폰·견적·사진·이력 13문서를 기존 관리자 권한으로 내보낸 뒤 암호화·복호화하고 격리 DB를 재구성한다. 복원 후 전체 경로·필드의 체크섬, 사진/이력 수, 서버에 저장된 Timestamp가 일치하는지 확인한다. 다른 UID/제공자 차단, 자료 변경 탐지, 취소·사진 수 불일치도 검사한다.

이는 실제 운영 DB 복원 검증을 대신하지 않는다. 운영 복원 UI와 자동 덮어쓰기는 제공하지 않는다. 사고 시 프로젝트 관리 권한이 있는 담당자가 파일을 비공개 환경에서 복호화·대조하고, 기존 자료와 충돌 여부를 검토한 뒤 승인된 복원 도구를 사용해야 한다. 기존 문서의 삭제·초기화·임의 덮어쓰기는 이 작업 범위에 포함하지 않는다. Firebase Auth 계정 복구는 별개다.
